# ADR-001: Globe Rendering Engine Selection

**Status:** Accepted

**Date:** 2026-08-14

---

## Context

The Radio Weather Globe is the primary interface for the entire application.

The visualization must support:

- Real-time animation
- Historical replay
- Signal arcs
- Multiple overlays
- Smooth rendering
- 60 FPS performance

The globe will become the application's defining user experience.

---

## Decision

Use Three.js as the primary globe-rendering engine.

Use Deck.gl for overlay rendering.

---

## Alternatives Considered

### Cesium

**Advantages**

- Mature geospatial ecosystem
- Excellent terrain support

**Disadvantages**

- Additional complexity
- More features than required

---

### Mapbox GL

**Advantages**

- Mature mapping platform
- Large ecosystem

**Disadvantages**

- Not designed for 3D globe-first interaction

---

### Three.js

**Advantages**

- Excellent animation support
- Fine-grained rendering control
- Strong integration with React

**Disadvantages**

- More custom implementation required

---

## Rationale

The application's primary differentiator is animated radio-weather visualization.

Three.js provides the greatest flexibility for creating the visual behaviors defined in the PRD, including:

- Pulsing regions
- Brightening paths
- Terminator animation
- Historical morphing
- Anomaly flares

---

## Consequences

### Positive

- Maximum visual flexibility
- Strong React integration
- Excellent animation capabilities

### Negative

- Additional development complexity
- More custom geospatial implementation
