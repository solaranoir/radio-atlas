# ADR-007: Implement a Multi-Factor Propagation Anomaly Detection Architecture

**Status:** Accepted

**Date:** 2026-08-14

**Authors:** SolaraSphere Engineering

---

## Context

Traditional amateur radio applications typically treat contacts as discrete events.

A contact either happened or it did not.

Statistics are usually limited to:

- DXCC counts
- Grid counts
- Distance
- Award progress
- Contact totals

Radio Atlas approaches contacts differently.

A contact should be evaluated in the context of:

- Solar conditions
- Geographic context
- Historical observations
- Band activity
- Propagation behavior
- Personal operating history

The system should identify events that deviate from expected behavior.

Examples include:

- A long-distance 10-meter contact during poor solar conditions
- A midnight 20-meter opening
- An unusually long propagation path
- A first-time DX entity
- A rare grid square
- An unexpected transpolar path

The competitive analysis revealed that anomaly detection is one of the few features capable of differentiating Radio Atlas from traditional logging software.

---

## Decision

Radio Atlas shall implement a dedicated propagation anomaly detection engine.

Anomalies shall be calculated from multiple weighted factors.

Anomalies shall be treated as independent domain objects.

Anomalies shall not be derived exclusively from distance.

The anomaly engine shall continuously analyze:

- Live observations
- Historical observations
- User contact history
- Replay data
- Forecast data

---

## Architectural Principles

An anomaly is not a single metric.

An anomaly is a statistical deviation from expected behavior.

The anomaly engine shall support:

- Geographic anomalies
- Temporal anomalies
- Propagation anomalies
- Personal operating anomalies

An anomaly score shall always be explainable.

## Alternatives Considered

### Option 1: Achievement-Based Detection

Assign badges when specific thresholds are reached.

Examples:

- 5,000-mile contact
- New DXCC entity
- New continent

#### Advantages

- Easy to understand
- Simple implementation

#### Disadvantages

- Static
- Binary
- Limited educational value

---

### Option 2: Rule-Based Anomaly Detection

Identify anomalies using predefined thresholds.

Examples:

- Distance > 5,000 miles
- Signal-to-noise ratio < -20 dB

#### Advantages

- Predictable
- Easy to test

#### Disadvantages

- Inflexible
- Difficult to extend
- May miss unusual patterns

---

### Option 3: Multi-Factor Anomaly Scoring (Selected)

Calculate anomalies using weighted statistical features.

#### Advantages

- More accurate
- More flexible
- More educational
- Better aligned with the Radio Atlas mission

#### Disadvantages

- Increased complexity
- More computational overhead

---

## Rationale

A 5,000-mile contact is not automatically unusual.

A 1,500-mile contact might actually be much more interesting if:

- It occurred on an unexpected band.
- It crossed the gray line.
- It occurred during poor solar conditions.
- It followed an unusual path.

The anomaly engine should evaluate context rather than relying on arbitrary thresholds.

---

## Anomaly Score

Scores shall be normalized.

```text
0.00 to 0.25 = Common

0.26 to 0.50 = Unusual

0.51 to 0.75 = Rare

0.76 to 1.00 = Exceptional
```

## Visualization Requirements

Anomalies shall be visible throughout the application.

---

### Live Globe

Anomalous paths shall:

- Flare briefly
- Increase in brightness
- Use distinct visual effects

---

### Replay Mode

Replay shall visualize:

- When anomalies appeared
- How anomalies evolved
- Which propagation conditions contributed

---

### Contact Intelligence Panel

The panel shall display:

- Unusual contacts
- Supporting evidence
- Similar historical contacts

---

## AI Integration

The AI layer shall explain anomalies.

Example:

> This contact was classified as exceptional because it combined a 5,200-mile path, gray-line enhancement, and a low-probability operating window.

AI explanations shall reference measurable evidence.

This requirement shall follow ADR-004.

---

## Achievement Integration

Achievements shall be derived from anomalies.

Examples:

| Achievement | Trigger |
| --- | --- |
| Longest Path | Personal distance anomaly |
| Midnight DX | Temporal anomaly |
| Polar Crossing | Geographic anomaly |
| Gray-Line Hunter | Propagation anomaly |
| Rare Grid Explorer | Grid rarity anomaly |

Achievements shall be a presentation layer rather than the underlying detection mechanism.
