# ADR-004: Implement an Evidence-Grounded AI Architecture

**Status:** Accepted

**Date:** 2026-08-14

**Authors:** SolaraSphere Engineering

---

## Context

Traditional amateur radio software generally performs one of two functions:

* It presents raw data.
* It performs calculations.

Radio Atlas introduces a third capability:

**Interpretation.**

The application should answer questions such as:

* Why did this contact occur?
* Why did this propagation opening appear?
* Why is 20 meters performing well today?
* Why did an anomalous path develop?
* Why are conditions changing?

Large language models can generate natural-language explanations.

However, AI systems also introduce significant risks:

* Hallucinations
* Unsupported conclusions
* Misinterpretation of scientific data
* Loss of user trust

The competitive analysis revealed that many existing AI-enhanced applications position AI as a conversational interface or a recommendation engine.

Radio Atlas should adopt a different approach.

The AI should function as an **evidence-based interpretation layer rather than an autonomous decision-making system.**

---

## Decision

All AI-generated content shall be derived from explicitly identified evidence.

The AI layer shall consume only structured, validated inputs.

The AI shall never access raw external APIs directly.

The AI shall never generate conclusions that cannot be traced to supporting observations.

The application shall visually distinguish among:

* Observed data
* Modeled data
* AI-generated interpretations

## Alternatives Considered

### Option 1: AI Chatbot

Allow users to ask free-form questions through a conversational interface.

#### Advantages

* Familiar user experience
* Flexible interactions
* Easier implementation

#### Disadvantages

* Increased hallucination risk
* Weak evidence attribution
* Reduced scientific transparency
* Less structured outputs

---

### Option 2: Evidence-Grounded AI (Selected)

Generate AI output only from validated, structured evidence.

#### Advantages

* Higher trust
* Better explainability
* Improved scientific accuracy
* Easier validation
* Better educational value

#### Disadvantages

* More engineering complexity
* Additional validation requirements
* More restrictive prompting

---

### Option 3: Rule-Based Explanations

Replace AI entirely with deterministic templates.

#### Advantages

* Predictable outputs
* No hallucinations
* Easier testing

#### Disadvantages

* Limited flexibility
* Repetitive narratives
* Poor adaptability

---

## Rationale

The primary goal of Radio Atlas is **education through visualization.**

AI should help users understand radio phenomena.

AI should not:

* Replace operators
* Replace scientific models
* Replace propagation calculations
* Recommend operating decisions without evidence

The project's core workflow should remain:

```text
Observe
        ↓
Explain
        ↓
Predict
        ↓
Explore Through Time
```

The AI layer exists within the **Explain** phase.

---

## Architectural Decision

The AI system shall use a constrained pipeline.

```text
External Providers
        │
        ▼

Normalized Observations
        │
        ▼

Evidence Builder
        │
        ▼

Prompt Constructor
        │
        ▼

LLM Provider
        │
        ▼

Response Validator
        │
        ▼

Structured Interpretation
        │
        ▼

User Interface
```

---

## Required AI Components

### Evidence Builder

Responsible for:

* Data collection
* Context assembly
* Source attribution

The evidence builder shall collect:

* Solar conditions
* Band information
* Geographic information
* Historical comparisons
* Contact statistics
* Propagation metrics

---

### Prompt Constructor

Responsible for:

* Prompt templates
* Prompt versioning
* Input formatting

Prompts shall remain independent of application logic.

---

### AI Provider

Responsible for:

* LLM communication
* Structured generation

AI providers shall comply with the provider abstraction architecture defined in ADR-003.

---

### Response Validator

Responsible for:

* Hallucination detection
* Schema validation
* Evidence verification
* Output normalization

---

### Interpretation Engine

Responsible for generating:

* QSO stories
* Educational explanations
* Replay captions
* Contact narratives

---

## Output Requirements

AI responses shall expose supporting evidence.

Example:

```json
{
  "observation": {
    "distance_miles": 5200,
    "band": "20m",
    "solar_flux": 184,
    "kp_index": 2
  },
  "interpretation": {
    "summary": "The contact likely benefited from gray-line propagation.",
    "confidence": "high"
  }
}
```

---

## User Interface Requirements

AI-generated content shall always be visually separated from measured observations.

Every AI panel shall include:

### Observed Evidence

* Solar conditions
* Contact statistics
* Geographic information

### AI Interpretation

* Narrative explanation
* Contextual explanation
* Educational summary

### Confidence Indicator

* High
* Medium
* Low

---

## Prompt Storage Strategy

Prompts shall be stored separately from application logic.

```text
backend/

└── ai/
    └── prompts/

        ├── qso_story_v1.txt
        ├── educational_assistant_v1.txt
        ├── replay_caption_v1.txt
        ├── anomaly_explanation_v1.txt
        └── achievement_narrative_v1.txt
```
