# ADR-009: Establish a Semantic Visualization and Animation Architecture

**Status:** Accepted

**Date:** 2026-08-14

**Authors:** SolaraSphere Engineering

---

## Context

The Radio Weather Globe is the primary user interface for Radio Atlas.

Traditional amateur radio software communicates information through:

- Tables
- Lists
- Charts
- Numerical indicators
- Static maps

Radio Atlas adopts a different philosophy.

Users should be able to observe the globe for a short period of time and immediately recognize:

- Where activity is increasing
- Which bands are opening
- Where propagation is weakening
- How the gray line is moving
- Which contacts are unusual
- How conditions have changed over time

The competitive analysis revealed that existing software generally requires significant interpretation by the operator.

Radio Atlas should reduce cognitive load by encoding information directly into visual behavior.

---

## Decision

Animations shall communicate measurable information.

Animations shall never exist solely for aesthetic purposes.

Every animated element shall have a documented semantic meaning.

The visual language shall be standardized throughout the application.

---

## Core Design Principle

Every animation should answer one question:

> What information does this movement communicate?

If no meaningful answer exists, the animation should be removed.

---

## Visual Behavior Definitions

### Pulse = Spot Density

Meaning:

Regional activity concentration.

Implementation:

Regions shall pulse according to the number of active spots.

Examples:

| Activity Level | Behavior |
| --- | --- |
| Low | Slow pulse |
| Moderate | Medium pulse |
| High | Rapid pulse |

---

### Brightness = Propagation Strength

Meaning:

Signal activity and path strength.

Implementation:

Signal paths shall increase in brightness as propagation improves.

Examples:

| Relative Strength | Visual Behavior |
| --- | --- |
| Weak | Dim |
| Moderate | Normal |
| Strong | Bright |

---

### Dissolve = Opening or Closing

Meaning:

A propagation window is changing.

Implementation:

Signal paths shall fade in and fade out as openings develop or disappear.

Examples:

| State | Behavior |
| --- | --- |
| Opening | Fade in |
| Stable | Constant |
| Closing | Fade out |

---

### Sweep = Terminator Movement

Meaning:

Earth's day and night boundary.

Implementation:

The terminator shall move continuously across the globe.

The movement shall be astronomically accurate.

The sweep shall function as a contextual environmental layer rather than a dominant visual element.

---

### Morph = Temporal Change

Meaning:

Historical change over time.

Implementation:

Replay Mode shall transition smoothly between historical states.

The system shall avoid abrupt visual changes.

Examples:

| Event | Visual Behavior |
| --- | --- |
| Spot redistribution | Geographic morph |
| Band opening | Path emergence |
| Band closure | Path disappearance |

---

### Dashed Paths = Prediction

Meaning:

Future propagation.

Implementation:

Predicted paths shall always be visually distinct from observed paths.

Examples:

| Data Type | Visual Representation |
| --- | --- |
| Observed | Solid line |
| Forecast | Dashed line |

Users shall never confuse a prediction with a measurement.

---

### Flare = Anomaly

Meaning:

A statistically unusual event.

Implementation:

Anomalous contacts shall briefly flare.

Examples:

| Anomaly | Visualization |
| --- | --- |
| Long-path contact | Short flare |
| Polar crossing | Bright flare |
| Rare DX | Extended flare |

---

## Layer Hierarchy

Visual layers shall follow a consistent hierarchy.

```text
Priority 1 → Active signal paths

Priority 2 → User-selected contacts

Priority 3 → Anomalies

Priority 4 → Forecast overlays

Priority 5 → Gray line

Priority 6 → Solar overlays

Priority 7 → Geographic overlays

Priority 8 → Basemap
```

Higher-priority layers shall never be visually obscured by lower-priority layers.

---

## Animation Timing Standards

Animation durations shall remain consistent throughout the application.

| Interaction | Duration |
| --- | --- |
| Panel transitions | 200 ms |
| Layer transitions | 300 ms |
| Signal updates | 500 ms |
| Path emergence | 750 ms |
| Replay transitions | 1,000 ms |
| Globe camera movement | 1,200 ms |

---

## Replay Mode Requirements

Replay Mode shall synchronize all animations.

The following elements shall update simultaneously:

- Signal paths
- Spot density
- Gray-line movement
- Solar conditions
- Forecast overlays
- Anomaly events

Animations shall remain deterministic.

Replaying the same time window should always produce identical visual results.

---

## Mobile Requirements

Animations shall adapt to device capabilities.

Mobile devices shall prioritize:

- Frame-rate stability
- Reduced GPU utilization
- Battery efficiency

Animation complexity may be reduced automatically.

---

## Accessibility Requirements

Users shall be able to:

- Reduce motion
- Disable animations
- Simplify visual effects

The application shall respect operating system accessibility preferences.

Color shall never function as the sole communication mechanism.

Alternative indicators shall include:

- Labels
- Icons
- Shapes
- Patterns
