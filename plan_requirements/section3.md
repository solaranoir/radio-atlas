# 3. User Personas

The design philosophy behind Radio Atlas assumes that amateur radio operators are not a single, homogeneous audience.

Traditional radio software often assumes that all users are experienced operators who already understand propagation, DXing, digital modes, and space weather.

Radio Atlas deliberately targets multiple experience levels and operating styles.

Unlike traditional radio applications that focus primarily on logging and operating, Radio Atlas also supports learning, exploration, scientific observation, and visual storytelling.

The product should remain technically sophisticated while remaining visually approachable.

---

## Persona 1: The Explorer

### Profile

**Name:** Sarah

**Age:** 34

**License:** General Class

**Operating Style:** Casual operator, traveler, portable operator

**Primary Devices:** Laptop, tablet, smartphone

### Biography

Sarah enjoys portable operation, travel, and making contacts while exploring new locations.

She enjoys operating but is less interested in the underlying science.

She frequently asks questions such as:

* Which band should I use?
* Why isn't my radio working today?
* Why can I suddenly hear Europe?

### Goals

* Find open bands quickly
* Make more contacts
* Understand propagation
* Improve operating decisions

### Pain Points

* Too many disconnected applications
* Complex propagation data
* Difficult visualizations
* Limited mobile support

### Features Used Most Frequently

* Radio Weather Globe
* Radio Forecast
* QSO Story

## Persona 2: The Observer

### Profile

**Name:** Elena

**Age:** 39

**License:** Amateur Extra

**Operating Style:** Scientific observation and experimentation

**Primary Devices:** Desktop workstation

### Biography

Elena is fascinated by the ionosphere itself.

She treats amateur radio as an observational science and enjoys watching propagation evolve.

She may spend as much time observing the globe as she does transmitting.

### Goals

* Observe propagation patterns
* Understand ionospheric behavior
* Explore global radio activity
* Identify unusual events

### Pain Points

* Existing software is overly transactional
* Most tools emphasize contacts rather than understanding
* Historical visualization tools are limited

### Features Used Most Frequently

* Radio Weather Globe
* Propagation Time Machine
* Anomaly Detection

## Persona 5: The Educator

### Profile

**Name:** Jennifer

**Age:** 42

**License:** General Class

**Operating Style:** Club instructor and mentor

**Primary Devices:** Laptop and projector

### Biography

Jennifer teaches licensing classes and introduces new operators to radio.

She frequently demonstrates concepts such as:

* Gray line propagation
* Solar cycles
* Band openings
* Skip distance
* Ionospheric behavior

### Goals

* Teach radio concepts visually
* Explain propagation
* Make learning engaging
* Demonstrate invisible phenomena

### Pain Points

* Existing software lacks educational visualization
* Technical concepts are difficult to explain
* Historical demonstrations are difficult to recreate

### Features Used Most Frequently

* Propagation Time Machine
* Radio Weather Globe
* QSO Story

## Persona 6: The Portfolio Reviewer

### Profile

**Name:** Hiring Manager

**Operating Style:** Technical evaluation

**Primary Devices:** Desktop browser

### Biography

This persona represents a secondary audience.

The application functions as both a product and a professional portfolio.

The reviewer is evaluating:

* Engineering practices
* Architecture
* UI design
* AI integration
* Testing methodology
* Code organization

### Goals

* Assess technical competency
* Evaluate code quality
* Understand architectural decisions

### Pain Points

* Poor documentation
* Incomplete projects
* Weak UI design
* Missing tests

### Features Used Most Frequently

* Architecture documentation
* Source code
* Interactive demonstrations
